## Security research

**Five research repositories, from web vulnerabilities to malware analysis.**

These are learning-oriented prototypes, not audited security products. The descriptions below reflect research scope—not production readiness or measured detection accuracy.

### Malware analysis & network defense

| Repository | Research focus | Technical scope |
| :--- | :--- | :--- |
| **[Malware-HAILAMDEV](https://github.com/xuanhai0913/Malware-HAILAMDEV)** | Understanding suspicious executable files | Static-analysis code for hashes, metadata, strings, entropy and disassembly using Python, LIEF and Capstone. Broader workflows remain prototype work. |
| **[DDOS-HAILAMDEV](https://github.com/xuanhai0913/DDOS-HAILAMDEV)** | Availability and traffic patterns | Python monitoring and simulation prototypes. The simulator models synthetic connection records; its output is not a real-world DDoS benchmark. |

### Web security & remote-access labs

| Repository | Research focus | Engineering questions |
| :--- | :--- | :--- |
| **[SQLI-V1-HAILAMDEV](https://github.com/xuanhai0913/SQLI-V1-HAILAMDEV)** | SQL injection research | How does input cross the query boundary? Explore query construction, database adapters and the role of parameterized queries. |
| **[KLG-XSS-HAILAMDEV](https://github.com/xuanhai0913/KLG-XSS-HAILAMDEV)** | XSS and input-capture risks | Study browser execution contexts and sensitive-input exposure, with defensive lessons for rendering and trust boundaries. |
| **[RAT-HAILAMDEV](https://github.com/xuanhai0913/RAT-HAILAMDEV)** | Remote-access client/server lab | Python sockets, TLS 1.3, newline-delimited JSON and session management. A study in why encryption alone does not provide authorization. |

> **Responsible scope:** isolated labs and explicitly authorized systems only. Some repositories contain dual-use functionality. They are not intended for unauthorized access, surveillance, data collection or service disruption. Follow each repository's safety notes; do not expose research services to public networks.

**See the reasoning, not just the repo names:**

- [Security Hub — attack paths and defensive design](https://www.hailamdev.space/en/security)
- [RAT lab case study — architecture, limitations and lessons](https://www.hailamdev.space/en/projects/security-lab)

### What I bring back to full-stack development

- **Database boundaries:** separate values from query structure and limit database privileges.
- **Browser boundaries:** treat rich text, previews and embeds as untrusted input.
- **Service boundaries:** distinguish encryption from authentication and authorization.
- **Evidence-first thinking:** document what is implemented, incomplete and not yet validated.
